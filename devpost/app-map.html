TapWire · app map · snapshot of commit 71b0ce0

Where things live

TapWire is two programs that share two JSON files. A command-line tool (scar) writes .scars/scars.json and .scars/events.json inside a repo; a Next.js dashboard reads the same files and draws the Amnesia Rate. This map follows one action, catching a repeat, through the code. It is a reference route: nobody has walked it with you yet, and it is a snapshot that can drift as the code changes.

One action, end to end

A route through the code

  1. The command

    packages/cli/src/index.ts → the check command

    Parses options, calls checkRepo, prints each hit with the scar's title, file, line and the correct pattern, and sets the exit code to 1 when it finds a repeat. This is what the pre-commit hook runs.

  2. The check

    packages/core/src/check.ts → checkRepo, checkDiff

    Runs git diff, reads the added lines, runs the regex matcher first and then the semantic pass (an LLM in live mode, a normalised pattern match in mock mode), removes duplicates and records one repeat event per hit with addEvent.

  3. The rate and the screen

    packages/core/src/rate.ts → computeAmnesiaRate · apps/dashboard/lib/data.ts → loadRepo · apps/dashboard/app/page.tsx

    loadRepo reads the JSON files, computeAmnesiaRate divides repeats by repeats plus new mistakes, and the Overview page draws the result. The page refreshes itself every few seconds, so a repeat caught in the terminal appears without a reload.

A practice to reuse

Test what must not match, not only what must

The first version of the mock semantic matcher compared words and flagged the corrected code (const user = await loadUser(id)) as a repeat of the mistake it was meant to catch. Writing the negative case, “does not flag the corrected code”, in packages/core/test/core.test.ts exposed it, and the matcher was rewritten. The change is recorded in devpost/checklist.md under Revisions.

On another project: for any rule that detects something, write one test that it catches the bad input and one that it leaves the good input alone, before trusting it.

Run it again

npm install && npm run demo, then open localhost:3000. In a second terminal: npm run demo:capture, then npm run demo:repeat. Tests: npm test.

Mock mode (SCAR_MOCK=1) needs no API key; the demo scripts set it for you.
